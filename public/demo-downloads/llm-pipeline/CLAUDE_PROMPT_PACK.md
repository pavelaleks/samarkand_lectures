# Claude / Cursor · prompt pack для LLM-конвейера по «Тёмным аллеям» (Л11)

Как пользоваться: копируйте блоки целиком, заменяя `<…>`. В **Claude Projects** загрузите в Project knowledge этот файл, свой `pipeline_design.md`, `run_pipeline.py` и один промпт из `prompts/`. В **Cursor** откройте папку проекта и пишите в чат агента — он видит файлы.

Главное правило: **Claude — помощник по дизайну, коду и самопроверке. Не источник цитат, не источник выводов о Бунине.** Все цитаты и все выводы проверяются по `sample_texts/`.

---

## 0. Системная роль для проекта (Claude Projects → Custom instructions)

```
Ты помогаешь студенту-филологу строить воспроизводимый LLM-конвейер по циклу
И. А. Бунина «Тёмные аллеи» (скрипт run_pipeline.py, DeepSeek API, промпты в prompts/).
Правила:
- Не придумывай цитаты из Бунина. Если цитата нужна — скажи «проверьте по sample_texts/».
- Не делай выводов о цикле в целом: мы работаем с таблицей кандидатов, выводы — после аудита.
- Предлагая поля JSON, всегда добавляй правило честного нуля.
- Код — минимальные правки run_pipeline.py, без новых зависимостей без необходимости.
- Ключ API никогда не вписывай в код: только .env / переменная окружения.
Отвечай по-русски, кратко, по шагам.
```

## 1. От интуиции к операционализации

```
Моя исследовательская интуиция: <например: «в финалах Тёмных аллей героини
помнят, а герои забывают»>.

Помоги превратить её в проверяемый признак для LLM-конвейера:
1. Сформулируй исследовательский вопрос одним предложением.
2. Дай операционализацию: при каких СЛОВЕСНО ВИДИМЫХ условиях во фрагменте
   признак засчитывается, а при каких — нет. Приведи 2 пограничных случая.
3. Предложи единицу фрагмента (начало / финал / весь текст кусками по N знаков) и объясни выбор.
4. Скажи честно, можно ли этот признак поймать без LLM (словарём, регуляркой, NER).
   Если можно — так и скажи, API тогда не нужен.
Не приводи цитат из Бунина.
```

## 2. Спроектировать поля JSON

```
Вопрос: <…>
Операционализация: <…>

Предложи контракт JSON для одной строки таблицы:
- базовые поля: id, thesis, quotes, confidence, flags (не меняй их смысл);
- 2–3 специальных поля под мой признак: имя_латиницей, тип, допустимые значения;
- закрытый список flags (4–5 штук), включая флаг отсутствия признака (no_…_evidence);
- правило честного нуля: какие значения должны быть у всех полей, если признака нет.
Для каждого поля: как я буду его ПРОВЕРЯТЬ по тексту за 30 секунд.
Поле, которое невозможно проверить, — убери.
Ответ — в формате строк «- "ключ": описание», чтобы я вставил его в prompts/<имя>_v1.md.
```

## 3. Написать промпт-файл

```
Вот образец промпта: <вставьте prompts/irony_v1.md>
Вот мой дизайн: <вставьте результат шага 2>

Собери prompts/<имя>_v1.md по той же структуре: роль «измерительный инструмент»,
вопрос, операционализация, ключи строками - "ключ": описание, разрешённые flags,
правило честного нуля, список запретов. Ничего не добавляй «для красоты».
```

## 4. Адаптировать run_pipeline.py

```
В проекте run_pipeline.py (прикреплён). Нужно: <одно изменение, например:
«добавить колонку n_words с длиной фрагмента» / «резать фрагменты по главам,
если в тексте есть римские цифры» / «добавить --stories-file со списком slug»>.

Требования:
- минимальный diff, покажи только изменённые функции;
- не трогай логику проверки цитат и запись output/raw;
- объясни, как проверить, что изменение работает (команда с --limit 2 или --dry-run).
```

## 5. Разобрать ошибку

```
Запускаю: python run_pipeline.py <аргументы>
Вывод терминала:
<вставьте целиком, БЕЗ ключа>

Что пошло не так и что сделать? Если ошибка в output/errors/<id>.txt — вот её текст: <…>
```

## 6. Протокол аудита (после прогона)

```
Вот 5 строк из results.csv и соответствующие фрагменты (из output/raw/*.json → fragment.text):
<вставьте>

Для каждой строки помоги мне проверить, НЕ подсказывая ответ заранее:
1. Найди каждую цитату в тексте фрагмента — есть дословно или нет?
2. Следует ли thesis из цитат — или это «вчитывание»?
3. Соблюдено ли правило операционализации из промпта?
Ответь таблицей id | цитата найдена | тезис обоснован | правило | моё решение: ___
Колонку решения оставь пустой — её заполняю я.
```

## 7. Улучшить промпт по итогам аудита

```
Промпт prompts/<имя>_v1.md: <вставьте>
Брак по аудиту (fail) и мои комментарии: <вставьте 3–5 строк>

Предложи prompts/<имя>_v2.md: что поменять, чтобы этих ошибок стало меньше.
Не расширяй признак, а сужай. Отдельно перечисли изменения списком — я запишу их в лог.
```

## 8. Формула прозрачности для текста работы

```
Данные прогона: модель <…>, temperature <…>, промпт <версия>, строк N,
цитат не из текста K, проверено вручную M, отклонено F.
Напиши 3–4 предложения для раздела «Метод»: что сделала модель, что сделал
исследователь, на каких строках строится интерпретация. Без оценочных слов
«мощный», «революционный».
```

## Чего НЕ просить у Claude

| Не просите | Почему | Вместо этого |
|---|---|---|
| «Найди все примеры иронии в Тёмных аллеях» | Claude по памяти выдумает цитаты и смешает редакции | прогоните конвейер по `sample_texts/` |
| «Процитируй финал “Натали”» | цитата по памяти ≠ текст | откройте файл |
| «Сделай вывод о цикле по моей таблице» до аудита | вывод на непроверенных строках | сначала аудит |
| «Поставь pass/fail за меня» | аудит — ответственность исследователя | шаг 6: пусть поможет найти цитату, решение — ваше |
| «Вставь мой ключ в скрипт» | ключ утечёт с первым коммитом | `.env` |
| «Сделай промпт, чтобы модель всегда находила приём» | наводка = фабрика псевдооткрытий | честный ноль, см. `irony_leading_v0.md` |
